# Security Audit & Hardening Report
**Project:** Local College Intelligence ("C-GPT")  
**Scope:** Application, Network, Database, and Model Security  
**Audit Standard:** OWASP Top 10 API Security / Institutional Data Governance  
**Auditor Classification:** Confidential Internal Technical Audit

---

## 1. Threat Model & Asset Inventory

In an educational institution, the primary assets requiring protection are:
1. **Confidential Student Records:** CIE test scores, attendance percentages, disciplinary warnings.
2. **Confidential Regulatory Documents:** Faculty appraisal metrics, moderation committee minutes, confidential examination circulars.
3. **Database Integrity:** Preventing unauthorized drops, alterations, or record overwrites.
4. **Compute Resources:** Preventing denial-of-service through continuous GPU exhaustion loops.

### Finding SEC-01 [CRITICAL]: Unsigned Client-Supplied Role Parameter
- **Location:** `backend/main.py` (`@app.post("/ask-docs")`)
- **Current Behavior:**
  ```python
  @app.post("/ask-docs")
  def ask_docs(req: AskDocsRequest):
      result = answer_question(
          question=req.question,
          role=req.role,  # <-- Taken directly from client request body
      )
  ```
- **Vulnerability Explanation:** An attacker can issue a curl or API request specifying `"role": "admin"` or `"role": "hod"`. Even if logged in as a student in the frontend, the backend will trust the request body and retrieve administrative policy chunks.
- **Remediation:**
  1. Derive role exclusively from a verified session token in the `Authorization: Bearer <token>` header.
  2. Implement a strict FastAPI dependency:
     ```python
     def get_current_user(token: str = Header(...)):
         user = get_user_by_token(token)
         if not user:
             raise HTTPException(status_code=401, detail="Invalid token")
         return user
     ```
  3. Set `role = current_user["role"]`.

### Finding SEC-02 [CRITICAL]: Regex-Based SQL Safety Filter Bypass Risk
- **Location:** `backend/main.py` (`@app.post("/ask-sql")`)
- **Current Behavior:** The SQL query generated by the LLM is checked via substring and regex:
  ```python
  BLOCKED = ["DROP", "DELETE", "UPDATE", "INSERT", "ALTER", "TRUNCATE", ...]
  if any(b in sql_upper for b in BLOCKED):
      return {"error": "Write queries blocked"}
  ```
- **Vulnerability Explanation:**
  - Multiple stacked queries: An adversarial generation such as `SELECT * FROM attendance; ATTACH DATABASE ...;` or clever comment obfuscation (`SELECT /*!50000 1*/ ...`) can evade simple keyword matching while still executing destructive SQLite operations.
- **Remediation:**
  - Replace regex with `sqlparse`:
    ```python
    import sqlparse
    statements = sqlparse.parse(raw_sql)
    if len(statements) != 1:
        raise ValueError("Multiple statements rejected")
    if statements[0].get_type() != "SELECT":
        raise ValueError("Only single SELECT queries allowed")
    ```

### Finding SEC-03 [HIGH]: Lack of API Rate Limiting on Compute Endpoints
- **Location:** `/ask-sql`, `/ask-docs`, `/api/chat`
- **Current Behavior:** Endpoints process incoming requests without rate limiting.
- **Vulnerability Explanation:** An automated script sending 50 requests per minute will saturate the GPU or CPU inference worker, denying service to genuine student and faculty queries.
- **Remediation:**
  - Implement `slowapi`:
    ```python
    from slowapi import Limiter
    from slowapi.util import get_remote_address
    limiter = Limiter(key_func=get_remote_address)
    @app.post("/ask-docs")
    @limiter.limit("10/minute")
    def ask_docs(...):
    ```

### Finding SEC-04 [HIGH]: Unbounded File Upload Size & Inadequate MIME Validation
- **Location:** `backend/main.py` (`@app.post("/upload")`)
- **Current Behavior:** Files are read entirely into memory (`raw_bytes = await file.read()`) with extension-based validation only.
- **Vulnerability Explanation:**
  - Memory exhaustion if a user uploads a 2 GB file.
  - A malicious executable renamed to `.csv` could be uploaded to `structured_data/`.
- **Remediation:**
  - Add file size cap:
    ```python
    MAX_FILE_SIZE = 50 * 1024 * 1024  # 50 MB
    if len(raw_bytes) > MAX_FILE_SIZE:
        raise HTTPException(413, "File exceeds 50MB limit")
    ```
  - Verify header magic bytes using `python-magic`.

### Finding SEC-05 [MEDIUM]: Missing Transport Layer Encryption in Direct LAN Deployment
- **Location:** Campus LAN subnet
- **Current Behavior:** Development relies on SSH port forwarding. If deployed directly on LAN without SSH, plain HTTP (ports 8000, 3000) transmits student queries and session tokens in cleartext over campus Wi-Fi.
- **Remediation:**
  - Deploy Nginx reverse proxy on the compute host configured with a local institutional SSL/TLS certificate (HTTPS only, redirect HTTP port 80 to 443).

---

### Finding SEC-06 [MEDIUM]: Exposure of Database Files in Git / Workspace
- **Location:** Root directory
- **Current Status:** Verified mitigated in `.gitignore` (`data/`, `*.db`, `*.sqlite` are gitignored).
- **Hardening Recommendation:** Add pre-commit hook to block accidental commits of `.db` files or files containing private USN lists.

## 3. Summary of Current Protections (Verified Working)
- ✅ Institutional data (`institutional.db`) is physically isolated from application user storage (`app_storage.db`).
- ✅ Passwords hashed with PBKDF2-SHA256 (100,000 iterations, random salt).
- ✅ Access control enforced inside ChromaDB vector store before text leaves the database.
- ✅ Uploaded filenames sanitized using alphanumeric regex `[^\w\.\-]` preventing directory traversal (`../../etc/passwd`).
- ✅ Ollama model restricted from external network calls (`think: False`, `/no_think`).
